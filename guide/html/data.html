1. 구조

www/data/화면ID.json서버 응답 예시. 열 이름은 Supabase(PostgreSQL) 테이블로 그대로 옮길 수 있게 snake_case, 시각은 ISO 8601 + 한국 시간.
www/js/data.js데이터 계층. 화면은 CescoData.load(화면ID)만 부릅니다. 출처를 바꿀 때는 이 파일의 source() 한 곳만 바꿉니다(지금 JSON → Supabase · 사내 API).
www/js/render.js데이터 → 화면. 줄 모양은 화면 HTML의 <template data-tpl>을 복제해 퍼블 클래스가 그대로입니다. 체크 · 거르기 · 모두 읽음처럼 데이터를 바꾸는 동작도 여기서 처리합니다(저장 API 연결 전에는 화면에서만).
범위8화면 모두 명세 · 예시 JSON이 있고, 업무 · 알림은 실제로 데이터로 그려집니다(체크 · 거르기 · 모두 읽음 · 상태 전환). 나머지 6화면도 같은 방식으로 render.js에 붙이면 됩니다.
확인같은 데이터로 다시 그린 화면이 퍼블 HTML과 픽셀 단위로 같음을 빌드 검증에서 확인했습니다.

필드

열형식필수화면에서

  • 「시연용 · 역할 바꿔 보기」는 퍼블 확인용 — 개발에서 뺌

SC 홈 MOW-SC-010101 · 명세 · 예시 JSON

테이블RPC get_home_summary (visits · timesheets · contracts · user_services · activities) · 응답 객체 하나
가져오는 것SC 홈 한 번에: 오늘 방문 · 다음 방문 · 근무 · 계약 · 홈 서비스 · 최근 활동
Supabase 예supabase.rpc('get_home_summary', { role: 'SC' })
예시 파일www/data/MOW-SC-010101.json · 화면 보기 →

필드

열형식필수화면에서
as_oftimestamptz필수서버 기준 시각 → 시간 막대의 「지금」 선 · 남은 시간
user.name · roletext필수제목 「김민준 SC님」
visits_today[]array필수시간 막대 블록 — start_at · end_at · status(done · next · later) · moved_from(바뀌기 전 시각)
next_visitobject선택다음 방문 카드 — customer_name · start_at · service_type · address_short · last_visit_at · phone(전화) · lat/lng(길찾기). 없으면 카드 숨김
work_weekobject필수이번 주 근무 worked_hours / target_hours · visible(전체 화면의 공개 설정)
contract_monthobject필수이번 달 계약 amount · target → 「목표까지」 = target − amount
home_services[]array필수주요 서비스 8칸 (사용자 순서, 주요서비스 편집과 같은 데이터)
recent_activities[]array필수최근 활동 3건 — customer_name · action · at · status(done · doing · wait)

표시 규칙

  • 시간 막대: 9~18시 축, 블록 위치 = start_at~end_at, 지난 시간은 흐리게
  • 제목 강조 = 다음 방문 「HH:MM 업체명」, 없으면 「오늘 남은 방문이 없어요」
  • 「N곳 완료 · M곳 남음」 = visits_today 의 status 개수, moved_from 있으면 「업체 HH:MM으로 변경」
  • 남은 시간 = next_visit.start_at − as_of (「1시간 50분 뒤」)
  • 금액은 만원 단위 · 천 단위 쉼표
  • 활동 시각: 오늘 HH:MM · 어제 HH:MM · M월 D일

L 불러오는 중서버 값만 스켈레톤 — 로고 · 구역 제목 · 서비스 칸 모양 · 하단 탭은 그대로
